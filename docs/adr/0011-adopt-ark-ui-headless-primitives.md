# 対話的 UI プリミティブに ark-ui（ヘッドレス）を採用する

`SlideList` の listbox を皮切りに、フォーカス・キーボード・選択状態を伴う対話的 UI プリミティブは ark-ui (Svelte) を標準採用する。スタイルは ark-ui のパーツを直接使い、`data-[state=...]` などのデータ属性に対してインライン Tailwind を当てる（ラッパー層は作らない）。これまで `SlideList` は ARIA の状態機械（矢印・Home/End・フォーカス管理）を自前で実装していたが、保守された a11y プリミティブに委ね、再発明をやめる。

## Considered Options

- **手書きの ARIA 実装を継続**: 却下。キーボード・フォーカス・選択の状態機械を部品ごとに再実装する負担が大きく、a11y のエッジケースを取りこぼしやすい。
- **スタイル付きコンポーネントライブラリ（shadcn-svelte / bits-ui 等）**: 却下。独自のラッパー層・スタイルの意見を持ち込み、「最小レイヤ・共有コードを持たない」という本リポジトリの志向（[[0002-two-packages-zero-shared-code]]）と衝突する。
- **薄いラッパーコンポーネント層を自前で用意**: 却下（現時点）。同一プリミティブを複数箇所で同一スタイル使う重複が実際に現れるまでは、インライン Tailwind で足り、抽象化は空回りする。

## Consequences

- ark-ui 経由で zag-js（状態機械）への依存重量を受け入れる。
- 移行に伴い `SlideList` の PageUp/PageDown（±5 ジャンプ）を廃止した。ARIA listbox の標準キーバインドではなく、ark-ui の状態機械と相性が悪いため。標準のナビゲーション（矢印・Home/End）は維持される。
- 今後の対話的 UI（ラジオグループ・ダイアログ・メニュー等）も ark-ui に寄せ、「ark-ui のパーツ＋データ属性バリアントでインライン Tailwind」という書き方を標準とする。
