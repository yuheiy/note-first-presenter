# スライドソースは設定で明示指定し、自動検出を廃止する

デッキは設定の `slides` が名指ししたファイルであり、未指定なら `slides.pdf` である。それ以外の何物でもない。以前は `slides` 未指定時に cwd 直下を `*.pdf` で glob し、ちょうど 1 件ならそれを採用、0 件なら「まだ無い」、2 件以上なら「曖昧」としていた。**ルールが暗黙的で、プロジェクトが使うデッキが「たまたま隣に何が置いてあるか」に依存していた**ため、明示的で単純なルールに置き換える。

配布用 PDF を 1 つ置いた、請求書を保存した、査読者から別バージョンが届いた — いずれも作業内容としては無関係なのに、以前はデッキの解決結果が変わった。新しいルールでは何も起きない。

## Considered Options

- **単一 PDF のみ自動検出を維持する**: 却下。「ちょうど 1 件」という条件は、動いているうちは説明する必要がなく、壊れて初めて存在に気づく類のルールである。しかも壊れ方が「PDF を追加したら別の場所でスライドが消えた」という、原因から最も遠い症状になる。
- **`slides.pdf` を優先し、無ければ単一 PDF に fallback する**: 却下。デフォルトが効いている限り予測可能に見えるが、fallback が発火した瞬間に上と同じ問題に戻る。分岐が 1 つ増えた分だけ説明が長くなり、得られる利便性は「ファイルを `slides.pdf` にリネームする」手間 1 回分でしかない。
- **設定を必須にし、デフォルトを持たない**: 却下。最も明示的だが、`slides.pdf` を置いて `note-first-presenter` と打つだけで始められる導線を失う。デフォルト値は 1 つの固定名なので、暗黙なのは「どの名前か」だけであり、「どのファイルか」ではない。

## Consequences

- `SlidesStatus` は `resolved` / `missing` の 2 アームになった。`configured-but-missing`（error 表示）と `no-config-no-file`（hint 表示）を分ける理由は、両者が同じ「設定が名指ししたパスに無い」状態に一本化された時点で消えた。クライアント側の `tone` と `SlidesMetaStatus` も同時に消滅し、メッセージは 3 本から 1 本になった。パスを文中に出すので、タイポも未配置も同じ 1 文で気づける。
- **UI 上は常に hint**。PDF を後からペアリングするのはこのツールの正規のワークフローであり、デッキ未配置は障害ではない。
- `SlidesStatus` は両アームとも絶対パスを持ち、人に見せる文字列に変える cwd 相対化は `slides.ts` の `forDisplay` 1 箇所を通る（`/nfp-data/meta.json`、`build` の成果物、`export` のエラー文言のすべて）。watcher と PDF リーダーは絶対パスを必要とし、ブラウザに著者のホームディレクトリを出す理由はない。
- watcher は 2 本に減った。cwd 直下の `*.pdf` を監視していた root watcher は不要になり、解決パス（存在しなくても）を dynamic watcher に渡すだけでよい — chokidar は監視中のパスにファイルが現れれば `add` を報告する。副次的に、`add` が `awaitWriteFinish` を経由するようになり、コピー途中の PDF を読む競合が消えた。**唯一の穴**は、デッキの親ディレクトリごと存在しない場合（`slides: 'assets/x.pdf'` で `assets/` が無い）にその後の作成を拾えないこと。dev の再起動が必要で、コストに見合わないため許容する。
- 対応外の拡張子（`slides: 'deck.key'`）は設定スキーマで弾く。これは「ファイルシステムの状態」ではなく「設定値の誤り」なので、`routerMode` の不正値と同じ経路 — 起動時 exit 1、dev 稼働中の編集は Vite の error overlay — を通る。検証しない場合の症状は pdfjs のパースエラーで、何を直せばよいか分からない。
- `tinyglobby` 依存が不要になった。
- ADR-0012 が保留していた「複数ソースファイルが同居した場合の優先順位」という宿題は消滅した。検出しないので優先順位が存在しない。ppt 追加時に必要になるのは glob の拡張ではなく、設定パスの拡張子から `Slides` 実装を選ぶディスパッチであり、それはまだ書かれていない（ADR-0012 を参照）。
