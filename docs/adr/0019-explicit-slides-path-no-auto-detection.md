# スライドソースは設定で明示指定し、自動検出を廃止する

デッキは設定の `slides` が名指ししたファイルであり、未指定なら `slides.pdf` である。それ以外の何物でもない。以前は `slides` 未指定時に cwd 直下を `*.pdf` で glob し「ちょうど1件なら採用」としていたが、**プロジェクトが使うデッキが「たまたま隣に何が置いてあるか」に依存していた**ため、明示的で単純なルールに置き換えた。

## Considered Options

- **単一 PDF のみ自動検出を維持**: 却下。壊れ方が「PDF を追加したら別の場所でスライドが消えた」という、原因から最も遠い症状になる。
- **`slides.pdf` 優先 + 単一 PDF に fallback**: 却下。fallback が発火した瞬間に同じ問題に戻り、得られる利便性はリネーム1回分でしかない。
- **設定必須（デフォルト無し）**: 却下。`slides.pdf` を置いて `note-first-presenter` と打つだけで始められる導線を失う。暗黙なのは「どの名前か」だけで「どのファイルか」ではない。

## Consequences

- `SlidesStatus` は `resolved` / `missing` の2アーム。**UI 上は常に hint** — PDF を後からペアリングするのはこのツールの正規のワークフローであり、デッキ未配置は障害ではない。パスを文中に出すので、タイポも未配置も同じ1文で気づける。
- 両アームとも絶対パスを持ち（watcher と PDF リーダーが必要とする）、人に見せる文字列への cwd 相対化は `forDisplay` 1箇所を通る。
- watcher は解決パス（存在しなくても）を監視するだけでよい。**唯一の穴**: デッキの親ディレクトリごと存在しない場合はその後の作成を拾えず dev の再起動が要る — コストに見合わないため許容。
- 対応外の拡張子は設定スキーマで弾く（「設定値の誤り」なので起動時 exit 1 の経路。検証しないと症状が pdfjs のパースエラーになり、何を直せばよいか分からない）。
- ADR-0012 が保留していた「複数ソース同居時の優先順位」という宿題は消滅した。ppt 追加時に必要なのは glob の拡張ではなく、設定パスの拡張子から `Slides` 実装を選ぶディスパッチである。
