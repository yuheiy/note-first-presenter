# `routerMode` と `base` を導入し、ルータライブラリは入れない

Amends: ADR-0014（ルーティングに関する判断のみ）

CLI に **`routerMode`（`'hash' | 'history'`、既定 `'history'`）** と **`base`** の2オプションを足す。HTML は `index.html` 1枚とその複製 `404.html` だけ。スライド番号はパスから外し **`?slide=` の search param** に移す。URL に関する知識は `packages/client/src/lib/routes.ts` 1本に集約する。名前と2値は Slidev の同名オプションから借りたが、URL の形は nfp 独自。

## 設計決定

### URL 設計: スライド番号は search param

|         | ワークスペース     | スライドショー                           |
| ------- | ------------------ | ---------------------------------------- |
| history | `/` ・ `/?slide=3` | `/slideshow` ・ `/slideshow?slide=3`     |
| hash    | `/` ・ `/?slide=3` | `/#/slideshow` ・ `/?slide=3#/slideshow` |

- **スライド1は常にパラメータ無し**で、`/1` にあたる URL は存在しない（`?slide=1` は `useActiveSlide` の書き戻しが消すので、リダイレクト専用コードはゼロ）。
- この選択の核心は**スライド番号がルーティングから完全に外れる**こと。ページ判定は `/slideshow` かどうかの1つだけになり、「`/999` と `/typo` の区別」という問いが問題ごと消える（スライド総数は `meta.json` を待つまで分からないので、URL からは原理的に判定できなかった）。
- **hash モードでも query は `#` の前**（実 `location.search`）。クエリはクエリとして扱われるべきで、`URLSearchParams` がそのまま読め、DevTools にもサーバログにも現れる。
- **ADR-0014 の「hash はサーバに届かない」という主張は破棄する。** 成り立たなくなったからではなく、守るべき性質として持ち歩くのをやめたから。**今後 hash モードに何かを足すとき「サーバに届いてしまうから」を却下理由にしてはならない。** 一方 `404.html` 不要・サブディレクトリで base 不要という hash モードの結論は生きている — 根拠は「ルートがリクエストに含まれない」という狭い事実の方である。

### 単一の HTML と、その複製

`404.html` は history モードで**主機能が動くための必須条件**（スライドショーは別窓への実 HTTP リクエストなので `GET /slideshow` が実際に飛ぶ）であって、ディープリンクへの配慮ではない。モードに関係なく無条件で出す（hash モードのサイトは到達しないだけで、出し分けるコストに利得が見合わない）。`_redirects` / `vercel.json` は出さない。

### `base`

ADR-0014 の「ハッシュ相対だからサブディレクトリで動く」は事実誤認だった（成果物の `<script src>` も `/nfp-data/*` も origin 絶対で、当時から壊れていた）。`base` は config のトップレベル + CLI 上書き（CLI が勝つ。GitHub Actions の `--base /${{ … }}/` は config に書ける値ではない）。Slidev はサブディレクトリ配信に hash を勧めるが、本 ADR は既定 history のまま base で正面から解く側を選ぶ。

### `lib/routes.ts` が URL 空間の唯一の所有者

モードと base の組み合わせはどれも「ちょうど1通り」しか正解がなく、間違えても型検査を通り、ルート直下では正しく動き、**サブディレクトリに置いた時だけ壊れる**。だから1箇所に集約して e2e（`e2e/subpath/`）で1度だけ踏む。個々の規則（base の付け方が用途で違う・hash では base 不使用・`?` の置き場所・スライドショー href は base 起点）の正本は `routes.ts` 自身のコメント。

### ルータライブラリを入れない

**wouter 3.10 を入れて全機能を完成させ、テストを通したうえで剥がした。** 決め手は `navigate` が1回も呼ばれていなかったこと — スライドショーは常に別窓で開き、クライアントサイド遷移がこのアプリには1つも存在しない。自前化は `resolveRoutePath` の約8行で足りた。再検討する人のために、wouter 固有の罠を残す:

- `<Link>` は `target` 属性を一切見ない（修飾キーだけ見て `preventDefault()` する）。このアプリ唯一のリンクがちょうど壊れるケースで、回避策も無い。
- `<Router base>` は末尾スラッシュを許さない（`path.slice(base.length)` の素朴な除去）。vue-router は正規化するので Slidev にはこの問題が無い。
- `useSearchParams` は hash モードでクエリを消せず、スライド1に戻れなくなる。

将来 in-document 遷移が実際に生まれた時点で再検討すればよい。

### その他の決定（詳細の正本はコード側コメント）

- **URL は `activeSlide` のミラー。** state が正、`replaceState` で書き戻し、読むのは初期値の1度きり、リスナ無し。`push` にしない理由: `activeSlide` はキャレットに追随するので、push だと `---` をまたぐたびに履歴が積まれる（Slidev が push できるのは移動が明示的操作だけだから）。方針は「slide index は replace、それ以外の遷移は push（現時点で存在しない)」。
- **モードの伝達は `define` 定数**（`'hash' | 'history'` の文字列リテラル。最初のレンダリング前に必要なので fetch では遅い）。定数を直接読む関数はテストしにくいので、`resolveRoutePath` / `composeSlideshowHref` はモードと base を引数で受け、定数を束ねるのは呼び出し側だけ。
- **dev も起動時の config エラーで即座に落とす**（間違った `routerMode` で動いているのか見分けられないため）。実行中の編集エラーは劣化して報告する。境界は「起動時は fail-fast、実行中は劣化」。
- **dev ミドルウェアは `configureServer` 内で直接 `use(base, mw)` する。** 後置フックは使えない — vite-plus は `htmlFallbackMiddleware` を post hook より前に `use()` するので、`/nfp-data/*` に到達しなくなる（実際に踏んで dev の e2e が全滅した）。base を剥がすのは connect のマウント機構の仕事で、ハンドラは base を知らない。

## Considered Options

- **`'memory'` を3値目に**: 却下。別窓に「お前はスライドショーだ」と伝える手段が URL しか無く、主機能が成立しない。
- **history モードでフォールバック文書を出さない**: 却下。GitHub Pages（「URL を綺麗にしたい」人が真っ先に置く先）で壊れる。
- **`base: './'` で資産だけ相対化**: 却下。history モードではルートの読み取りが自分のマウント位置を知る必要があり、相対では解けない。
- **スライド番号をパスに置く（Slidev の `/slideshow/3`）**: 却下。得られるのはディープリンクの見た目だけで、「slide index がルーティングに関与しない」性質の方が大きい。
- **hash モードで query をハッシュの中に**: 却下。クエリがクエリとして扱われなくなる。
- **`/` を `/1` に正規化**: 却下。共有 URL が `/`（静的ホスト上に実在するファイル）のままになる方を選んだ。
- **404 ページを作る**: 却下。2ページのアプリに3ページ目を足す価値がない。読めない URL は `/` に落とす。

## Consequences

- ADR-0014 のルーティング判断のうち置き換わるのは URL の形だけ。「ルータを入れない」「リスナを置かない」「URL は書き込み専用ミラー」「起動時に1度読む」は維持。
- `dev` コマンドが初めて config ファイルを読むようになった。クライアントの依存は1つも増えていない。
- 既定が history なので、rewrite 非対応ホストではスライドショーが `404.html` 経由で開く(URL は保持、ステータスは 404)。hash モードならその依存も消える。
